# Tablet background and speed plan — 2026-11-12

Goal: Samsung tablets and iPads. Background execution cannot be guaranteed by any web API (iPadOS suspends Safari within seconds; Chrome Android freezes pages and dedicated workers after 1 min, Android 14+ freezes cached processes; low-memory kills hit background tabs first), so make interrupted exports resumable instead of pretending they continue. Mobile only: persist finished parts (in-memory ZIP) or delivered parts (single files) in a separate IndexedDB database, restore cuts when the same file is reopened, release the idle engine when hidden, mobile worker with output pre-allocation and zero-copy transfer behind a ping probe and fallbacks. Desktop path unchanged. Verify: unit tests (fake IndexedDB, MEMFS patch, take/fallback), production build, Playwright app flows on Desktop Chrome, iPad (WebKit) and Galaxy Tab (Chromium without pickers), before/after timings and renderer RSS against the previous build, reload/crash/freeze/idle-release scenarios. Do not claim real-device behaviour (jetsam, Samsung Internet, quota) from emulation.
